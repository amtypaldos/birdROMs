# Platform alias research notes (birdROMs)

Outputs: `platform-aliases.csv` (138 rows; generated by `gen/build.py` from the fetched sources in `src/`).
Matching is case-insensitive; every alias is lower-case. Some aliases contain spaces (libretro names, e.g. `nintendo - game boy`).

## Sources (all fetched live, 2026-10-28)
- muOS assign data (primary, defines folder -> system): https://github.com/MustardOS/internal/blob/main/share/info/manifest/core.json  (per-system `friendly` arrays = the accepted folder names) and https://github.com/MustardOS/internal/blob/main/script/system/assign.sh (builds `assign.json` from every `friendly` entry).
- muOS folder display names: https://github.com/MustardOS/internal/blob/main/share/info/name/folder.json (folder key -> pretty name; tag `muos-folder.json`).
- muOS RetroArch playlist/icon names (libretro DB names): https://github.com/MustardOS/internal/tree/main/share/emulator/retroarch/assets/ozone/png/icons (tag `libretro`).
- Batocera: https://github.com/batocera-linux/batocera.linux/blob/master/package/batocera/emulationstation/batocera-es-system/es_systems.yml (top-level keys = ROM folder names).
- Knulli (Batocera fork): https://github.com/knulli-cfw/distribution/blob/knulli-main/package/batocera/emulationstation/batocera-es-system/es_systems.yml (tag `knulli` only for keys absent from Batocera).
- ROCKNIX: the repo has no static es_systems.cfg; I used the per-system emulator configs https://github.com/ROCKNIX/distribution/tree/next/projects/ROCKNIX/packages/ui/emulationstation/config/emulators (names = system/folder ids) plus `rocknix-systems` script. JELOS repo is gone (JELOS/JELOS 404; ROCKNIX is its successor), not fetched.
- AmberELEC: https://github.com/AmberELEC/AmberELEC/blob/main/packages/ui/emulationstation/config/es_systems.cfg (`<path>` dirs).
- ArkOS: https://github.com/christianhaitian/arkos/blob/main/12162020/es_systems.cfg (latest dated snapshot in repo, Dec 2020, so stale; `<path>` dirs).
- Onion OS: https://github.com/OnionUI/Onion (`static/build/App/Emu/*/config.json`, `rompath` = real Roms dir; tag `onion`).
- SpruceOS: https://github.com/spruceUI/spruceOS (branch Development, `Emu/*/config.json`; tag `spruce`).
- MinUI / NextUI: https://github.com/shauninman/MinUI and https://github.com/LoveRetro/NextUI `skeleton/*/Roms/` (folder pattern `Display Name (TAG)`; tag `minui/nextui`). Only the TAG matters; parse the text inside the LAST parentheses, e.g. `Super Nintendo Entertainment System (SUPA)` -> `supa`. The CSV contains the tags I saw (fc gb gba gbc md ps sfc mgba ngp ngpc p8 pkm gg sms sgb supa pce vb puae cpc fbn a2600 a5200 a7800 lynx coleco c128 c64 pet plus4 vic prboom fds msx 32x segacd sg1000).
- User card (tag `card`): 55 folders listed in the task / `birdroms-handheld/docs/b1-device-recon.md`. All 55 resolve to a row.
- NOT fetched / not covered (no usable primary source reachable): Garlic OS, TrimUI stock, stock Anbernic. Do not add aliases from them without a source.

## Key facts about muOS
- On muOS the folder name is just a key into `assign.json`; any `friendly` string above is a valid folder name. Pre-existing 55 folders on the card are one choice. `muos_folder` in the CSV = the card's folder when the card has one; otherwise a muOS-recognised alias that Onion/Spruce also use (note says "inferred"); otherwise empty (muOS recognises it but no convention to copy). Empty `muos_folder` with kind game: use `notes` for a suggested name.
- muOS folds several variants into one system: N64DD->N64, DSi->NDS, Satellaview/Sufami->SNES, NGPC->NGP, WSC->WS, Videopac->Odyssey2, SG-1000 stays separate, all arcade names (mame, fbneo, cps1-3, hbmame, pgm, varcade) are one `Arcade` system, Atomiswave+Naomi are one system. The CSV splits these back into separate rows where folders are distinct, so the importer can still classify by folder; `muos_folder` for the folded rows points at the shared folder.
- Odd card folders: **GW** = Nintendo Game & Watch (muOS/Onion/Spruce `gw`); **VARCADE** = vertical arcade sets (inferred; muOS friendly list only); **ONS** = ONScripter visual-novel engine (muOS core "Onscripter", friendly list has `story;visualstory`, NOT `ons`; card-only alias); **EASYRPG** = RPG Maker 2000/2003 via EasyRPG; **POKE** = Pokemon Mini (not Pokemon games); **PICO** = PICO-8 (not Sega Pico); **PGM2** = IGS PolyGame Master 2 arcade board (no source defines it; muOS has only `pgm`); **HBMAME** = homebrew/hack MAME set; **APPS/PORTS** = non-game launchers (muOS puts both in "External - Ports"); **SCUMMVM/OPENBOR** = engines (kind game; content is game data/scripts); **MDCD** = Mega-CD / Sega CD; **ATARI** = Atari 2600 (duplicate of A2600; muOS merges); **PS** = PlayStation 1.
- Non-game: APPS, PORTS (also muOS `media`/`music`/`video`, `books`, `karaoke`, `gamemusic` are non-game). Batocera `tools`, `imageviewer`, `recordings`, `library`, `windows`, `steam`, `flatpak` etc. are also non-game but I did not add rows (unmapped keys below).

## Ambiguities / conflicts between firmwares
- `pico`: PICO-8 in muOS (`pico8;pico`), Onion (`PICO`, `.p8`), but **Sega Pico** in Batocera/Knulli (`pico`; PICO-8 is `pico8`). CSV maps `pico` -> PICO-8 (matches the user card); `segapico` -> Sega Pico. Disambiguate by extension (`.p8`/`.p8.png` => PICO-8; `.md/.bin/.zip` => Sega Pico) if wanted.
- `ps`: PlayStation 1 everywhere seen (muOS, MinUI, Spruce, Onion rompath). ROCKNIX/Batocera call it `psx`; `ps2`/`ps3` are distinct systems there. Onion's emulator key is `PSX` but ROM dir `PS`.
- `gw`: Game & Watch in muOS/Onion/Spruce; Batocera uses `gameandwatch` and `lcdgames`.
- `poke`/`pkm`/`pokemini`: all Pokemon Mini.
- `atari`: Atari 2600 in muOS/Onion/Spruce. Not "generic Atari". Batocera/ROCKNIX use `atari2600`.
- `commodore`: C64 in muOS/Onion/Spruce.
- `ms`: Sega Master System (muOS/Onion/Spruce); `sms` same. `smsgg`/`ggsms` in muOS friendly are ambiguous SMS-vs-GG and are mapped to SMS (as muOS does).
- `md`: Mega Drive/Genesis in muOS, Onion, Spruce, MinUI. `mdcd` = Mega-CD. Onion/Spruce also have `msumd`.
- `pc`: DOS/PC in muOS; separate from `pc88`/`pc98`. `st` (muOS friendly) = Atari ST; ROCKNIX `st-v` is the unrelated Sega ST-V arcade board (unmapped).
- `ngp` folder is shared by NGP and NGPC on muOS (and MinUI has separate NGP/NGPC tags). Same for `ws` (WS+WSC). Distinguish by extension (.ngp/.ngc; .ws/.wsc).
- `sfc` / `snes` / `supa` all SNES; Onion/Spruce have separate `SUFAMI`, `SATELLAVIEW`, which muOS assign groups with SNES.
- `arcade`-type folder names: muOS puts mame, fbneo, fba, cps, cps1-3, hbmame, pgm, varcade, horizontal, vertical in ONE system. The CSV keeps them as separate rows; the bare word `cps` is ambiguous (CPS1/2/3) and is mapped to "Arcade (generic)".
- `32x`: muOS accepts `32x` and `sega32x` (card uses SEGA32X); Onion `THIRTYTWOX`; MinUI tag `32X`.
- `dc` Dreamcast (muOS, Spruce). `naomi`/`atomiswave`: same muOS system, separate folders on the card.
- `amiga` covers `amigacd32` here only because the muOS core list has a single Amiga system; Batocera/Amber/ROCKNIX have a separate CD32 system.
- muOS friendly lists contain emulator-ish strings (`kega`, `gens`, `bgb`, `mgba`, `snes9x`, `zsnes`, `epsxe`, `pcsx`, `pbp`, `redream`, `flycast`, `ppsspp`, `dosbox`) and the Sega Genesis list contains `nomad`; I kept them because they are in the source, but a scanner should treat them as low-confidence.
- Some muOS aliases are very short/generic and risky for fuzzy matching: `64`, `tg`, `ss`, `sat`, `pc`, `st`, `tt`, `ng`, `ms`, `gen`, `app`, `bk`, `gce`, `wolf`, `lua`, `story`, `media`. Use exact whole-folder matches only.
- ArkOS data is a Dec-2020 snapshot; Batocera/Knulli key sets are very large and mostly out of scope.

## Corrections / additions to the handheld client table (`internal/platforms/muos_folders.go`)
Checked against the card list and muOS core.json: **no existing entry is wrong.** All 22 pairs match a real folder on the card (FC, SFC, N64, GB, GBC, GBA, NDS, SMS, MD, GG, SEGA32X, DREAMCAST, PS, PSP, PCE, NGP, NGP, WS, WS, A2600, A7800, LYNX). Caveats and gaps:
1. `NGP` for NGPC and `WS` for WSC are correct (muOS has no NGPC/WSC folder; Spruce does). Keep as is.
2. `Atari 2600 -> A2600` fine; the card also has `ATARI` (same system, muOS merges both lists). Keep A2600.
3. `PC Engine / TurboGrafx-16 -> PCE` fine; **missing**: PC Engine CD -> `PCECD`, SuperGrafx -> `SGFX` (inferred, not on card).
4. **Missing platforms that exist on the card** (add to the table): Sega CD -> `MDCD`; Sega Saturn -> `SATURN`; Neo Geo -> `NEOGEO`; Neo Geo CD -> `NEOCD`; Famicom Disk System -> `FDS`; Virtual Boy -> `VB`; Pokemon Mini -> `POKE`; Game & Watch -> `GW`; Atari 5200 -> `A5200`; Atari 800 -> `A800`; Atari ST -> `ATARIST`; Amiga -> `AMIGA`; Commodore 64 -> `C64`; VIC-20 -> `VIC20`; MSX -> `MSX`; DOS -> `DOS`; ScummVM -> `SCUMMVM`; OpenBOR -> `OPENBOR`; EasyRPG -> `EASYRPG`; PICO-8 -> `PICO`; Atomiswave -> `ATOMISWAVE`; Naomi -> `NAOMI`; CPS1/2/3 -> `CPS1`/`CPS2`/`CPS3`; MAME -> `MAME`; FinalBurn Neo -> `FBNEO`; HBMAME -> `HBMAME`; Vertical arcade -> `VARCADE`; IGS PGM2 -> `PGM2`; ONScripter -> `ONS`.
5. Do not use the platform string as a path (already the case); the `Sega Genesis` display name should also accept "Mega Drive". Ambiguity to handle on the server side: Super Game Boy has no muOS folder (use `GB`), Satellaview/Sufami go to `SFC`, 3DS/GameCube/Wii/PS2+ have no muOS folder (leave `_UNSORTED` or skip).
6. If a different muOS card is used, prefer an existing folder: since muOS accepts any `friendly` alias, check which alias already exists on the card (case-insensitive on exFAT) instead of creating a second folder for the same system. E.g. `SFC` vs `SNES`, `MD` vs `GENESIS`, `PS` vs `PSX`.
