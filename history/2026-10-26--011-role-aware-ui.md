# 011 — Role-aware frontend

## Decisions
- Write access is a single `canWrite = me?.role === "super_admin"` in `App`. The Upload panel is
  not rendered and `RomList` gets `onScrape={null}`, so the Scrape button is never mounted for
  readonly users. Disabling them would have left dead UI.
- **Fail closed while loading**: until `api.me()` resolves, `me` is null and no write controls
  render. A slow `/me` call never briefly shows Upload to a readonly user.
- Backend `user_role` already maps Django superusers to `super_admin`, so the UI needs no
  separate `is_superuser` check.
- The session info moved into a `SessionBar` card with a role badge (`.role-badge`, `.admin`
  variant). These are small, neutral styles; the full retro restyle is spec 012.

## Notes for later specs
- 012: restyle `.session` / `.role-badge` along with the rest.
- The backend still enforces `IsSuperAdminOrReadOnly`. The UI gating is only UX, not security.
